# PRD: 캐릭터 수집형 RPG 게임 (마스터)

## 1. 문서 목적
- 본 문서는 **MVP 기준의 상위 요구사항**만 정의한다.
- 시스템별 상세 규칙은 하위 문서에서 관리한다.
- 구현 상세/장기 확장 항목을 분리하여 문서 중복을 최소화한다.

## 2. 문서 구조
- 캐릭터: [CHARACTER.md](./CHARACTER.md)
- 전투: [BATTLE.md](./BATTLE.md)
- 콘텐츠: [CONTENT.md](./CONTENT.md)
- 상점/재화: [SHOP.md](./SHOP.md)
- 추후 확장: [FUTURE.md](./FUTURE.md)

## 3. 제품 비전
- 서머너즈워 스타일의 핵심 루프(수집 → 성장 → 전투 → 보상)를 유지한다.
- 1인 개발 기준으로 시스템 복잡도를 낮추고, 반복 플레이 동기를 명확히 한다.

## 4. MVP 범위

### 4.1 포함
- 로그인/인증, 튜토리얼, 기본 몬스터 지급
- **대륙 홈 화면**: 플레이어 캐릭터 직접 조작, 보유 소환수 자유 배회
- 파티 편성, 스토리 던전(챕터 1~2), 전투 결과/보상
- 상점(일일 상점/가챠 상점), 소환, 성장(레벨업/각성)
- 에너지, 일일 퀘스트, 기본 로그/모니터링

### 4.2 제외
- PvP/길드/채팅/레이드
- 룬 시스템, 스킬 강화, 이벤트 던전
- 실시간 매칭/랭킹 고도화

제외 항목 상세는 [FUTURE.md](./FUTURE.md)에서 관리한다.

## 5. 핵심 게임 루프
1. 로그인/튜토리얼
2. **대륙 홈 화면** 진입 (플레이어·소환수 탐험)
3. 던전 선택 및 파티 편성
4. 전투 실행
5. 결과 확인 및 보상 수령
6. 상점/소환/성장 중 선택
7. 홈 화면으로 복귀 → 다음 스테이지 또는 일일 루틴 반복

## 6. 공통 시스템 원칙

### 6.1 상태 전이(요약)
- `Home(대륙)` → `DungeonSelect` → `PartyEdit` → `Battle` → `Result` → `RewardClaim` → `Home(대륙)`
- `Home(대륙)` ↔ `Shop` / `Summon` / `CharacterList` (UI 버튼 탭으로 전환)
- 에너지 부족 시 `Shop` 또는 다른 PvE 루트로 유도한다.

### 6.2 데이터 반영 원칙
- 전투 시작 시 파티 스냅샷을 저장한다.
- 전투 종료 후 승패/보상 계산은 서버에서 확정한다.
- 보상 수령은 단일 트랜잭션으로 처리한다.

### 6.3 경제/성장 원칙
- 골드는 성장 재료 중심, 크리스탈은 소환 중심으로 설계한다.
- 성장 루프는 "전투 → 보상 → 성장 → 상위 난이도 도전"을 유지한다.

## 7. 기술 아키텍처 (현재 레포 기준)

### 7.1 스택
- 프론트엔드: Phaser 3 + TypeScript + Vite
- 백엔드: TypeScript + Node.js + Express + Drizzle ORM
- 데이터베이스: PostgreSQL
- 캐시/세션: Valkey (Redis 호환)
- 인증: JWT(Access + Refresh), Refresh Token은 HttpOnly 쿠키 기반
- 인프라: Docker Compose + Nginx + Dozzle

### 7.2 통신
- REST API: `/api/v1/*`
- WebSocket: `/ws`

### 7.3 보안 기본값
- Access Token 수명: 15분
- Refresh Token 수명: 7일
- API Rate Limit: 분당 100 요청(기본값)

## 8. 비기능 요구사항 (MVP)
- API 평균 응답 시간: 200ms 이내 목표
- 클라이언트 목표 프레임: 60fps(저사양은 30fps 허용)
- 가로(landscape) 기준 UI 일관성 유지
- 주요 사용자 행동(로그인/전투/구매/소환) 구조화 로그 기록

## 9. 운영/지표

### 9.1 핵심 지표
- 플레이 지표: DAU, D1/D7 유지율, 평균 플레이 타임
- 경제 지표: 재화 획득/소비 균형, 소환 이용률
- 진행 지표: 스테이지 클리어율, 이탈 구간

### 9.2 리스크
- 밸런스 붕괴, 컨텐츠 소진, 부정행위
- 완화: 서버 검증, 데이터 기반 밸런스 패치, 단계적 확장

## 10. 문서 운영 규칙

## 11. 대륙 홈 화면 (Home World Screen)

### 11.1 개요
로그인 후 최초로 진입하는 메인 화면이다. 서머너즈워의 "섬" 화면처럼 플레이어가 소유한 소환수들이 대륙 위를 자유롭게 돌아다니며 생동감을 연출한다. 플레이어는 자신의 캐릭터를 직접 조작하여 대륙을 탐험하고, 상호작용 오브젝트를 통해 각 콘텐츠로 이동한다.

### 11.2 구성 요소

#### 11.2.1 대륙 맵
- Phaser 3 타일맵(Tiled JSON 포맷) 기반의 2D 탑다운 맵
- 스크롤 가능한 넓은 대륙 지형 — 구역 예시: 평원, 숲, 마을, 성, 제단
- 카메라는 플레이어 캐릭터를 중심으로 부드럽게 추적 (lerp 적용)
- 맵 경계는 카메라 클램프로 제한
- 타일맵 레이어 구성: `Ground` / `Decoration` / `Collision` (최소 3레이어)

#### 11.2.2 플레이어 캐릭터 (조작 캐릭터)
- 플레이어 전용 아바타 스프라이트(4방향 스프라이트시트)
- **PC 입력**: WASD / 방향키 — 8방향 이동
- **모바일 입력**: 화면 좌측 하단 가상 조이스틱 (Virtual Joystick Plugin)
- 이동 속도: 기본 120px/s / 달리기(Shift 또는 더블탭) 240px/s
- 충돌 처리: 타일맵 Collision 레이어 기반 (Phaser Arcade Physics)
- 이동 방향에 따라 스프라이트 애니메이션 전환 (up / down / left / right / idle)
- 플레이어 닉네임이 캐릭터 머리 위 이름표로 표시됨

#### 11.2.3 소환수 자유 배회 (Monster Roaming)
- 보유 소환수 중 최대 **6마리** 동시 배치, 대륙 위를 자율 이동
- 배치 우선순위: 현재 파티 편성 캐릭터 → 최근 획득 순
- Wander AI: 랜덤 웨이포인트 이동 → 대기 1~3초 → 다음 웨이포인트 반복
- 플레이어 캐릭터 근처 150px 이내 진입 시 플레이어를 따라오는 동작으로 전환
- 소환수를 클릭/탭 → 캐릭터 상세 팝업 표시 (CharacterDetailScene 재사용)
- 소환수 머리 위에 종족명 + 별점 이름표 표시
- AI 업데이트 주기: 500ms 틱 (매 프레임 연산 방지)

#### 11.2.4 HUD (고정 UI 레이어)
| 위치 | 요소 |
|---|---|
| 상단 중앙 | 재화 바 (크리스탈 / 골드 / 에너지) |
| 우측 세로 | 퀵메뉴 버튼 (던전 / 소환 / 상점 / 퀘스트) |
| 좌측 하단 | 가상 조이스틱 (모바일만 표시) |
| 우측 하단 | 메뉴 버튼 (인벤토리 / 설정) |

- 모든 HUD 요소는 `setScrollFactor(0)` 적용하여 카메라 스크롤에 고정

#### 11.2.5 상호작용 오브젝트
| 오브젝트 | 맵 구역 | 전환 씬 |
|---|---|---|
| 던전 입구 | 동쪽 | DungeonSelectScene |
| 소환 제단 | 중앙 | SummonScene |
| 상점 NPC | 마을 | ShopScene |
| 길드 홀 | 서쪽 | GuildScene |

- 플레이어가 오브젝트 반경 80px 이내 진입 시 상호작용 버튼([E] / 말풍선 아이콘) 표시
- 버튼 탭 또는 E / F 키로 씬 전환 트리거
- 퀵메뉴 버튼을 통해서도 동일하게 씬 전환 가능

### 11.3 씬 구조 (Phaser 3)
```
HomeScene
├── TilemapLayer (Ground → Decoration → Collision)
├── InteractiveObjects : StaticGroup
├── MonsterGroup : Group<MonsterSprite>  (≤6)
├── PlayerCharacter : Sprite + ArcadeBody
├── HUD : Container (setScrollFactor 0)
│   ├── ResourceBar
│   ├── QuickMenu
│   └── VirtualJoystick (mobile only)
└── Camera
    ├── startFollow(PlayerCharacter, lerp=0.1)
    └── setBounds(0, 0, mapWidth, mapHeight)
```

### 11.4 데이터 연동 (API)
| 시점 | 호출 API | 용도 |
|---|---|---|
| 홈 진입 시 | `GET /api/v1/user/profile` | 닉네임, 재화 표시 |
| 홈 진입 시 | `GET /api/v1/party` | 소환수 배치 우선순위 결정 |
| 홈 진입 시 | `GET /api/v1/characters` | 배회 소환수 목록 |
| 재화 변동 시 | 클라이언트 이벤트 버스 | HUD 실시간 갱신 (추가 API 호출 없음) |

- 소환수 배치 구성은 클라이언트 로컬 상태로만 관리 (서버 저장 불필요)

### 11.5 성능 기준
- 소환수 최대 6마리 + 플레이어 1 기준 60fps 유지 목표
- 타일맵 카메라 뷰포트 기준 자동 컬링 (Phaser 3 기본 제공)
- 소환수 AI 업데이트 주기 500ms로 제한하여 CPU 부하 절감

### 11.6 구현 우선순위
1. 타일맵 렌더링 + 플레이어 캐릭터 이동 (PC 키보드)
2. 카메라 추적 + HUD 고정
3. 소환수 배회 AI (최대 6마리)
4. 상호작용 오브젝트 + 씬 전환
5. 모바일 가상 조이스틱
6. 소환수 클릭 상세 팝업
